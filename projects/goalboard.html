Goalboard

A soccer analytics mobile app that surfaces live league standings, match results, and team performance trends — built with a React Native (Expo) front-end and a Python FastAPI back-end.

Overview

Goalboard is a cross-platform mobile app for soccer fans who want real data without the noise. It pulls league standings, recent match results, and team performance trends from the Soccerdata API and presents them in a clean, navigable interface. The project was motivated by wanting to build something full-stack that I actually use — and by the challenge of connecting a Python data layer to a mobile front-end.

This is my current project and the most technically broad thing I've built: it involves API design, data normalization, async mobile state management, and cross-platform UI — all wired together from scratch.

Problem

Existing soccer apps are cluttered. I wanted a focused view: standings, results, and trends — nothing else.

Solution

A FastAPI backend that normalizes Soccerdata output into clean REST endpoints, consumed by a React Native app.

My Role

Sole developer. Responsible for backend API design, data modeling, and the full mobile UI.

Tech Stack

Python FastAPI Soccerdata API React Native Expo REST APIs

What I Built

  • FastAPI REST backend — designed and implemented endpoints for league standings, recent matches, and team stats. Each endpoint normalizes raw Soccerdata output into a consistent response shape the app can rely on.
  • Soccerdata integration — wrapped the Soccerdata Python library to fetch live football data, handling rate limits and data normalization before passing results to the API layer.
  • React Native screens — built three core screens: Standings (tabular league table), Matches (recent results with scores), and Team Detail (aggregated performance stats for a selected team).
  • Expo configuration — set up the project for cross-platform deployment targeting both iOS and Android through Expo's managed workflow.
  • Async data fetching — managed API calls and loading states in React Native using async/await with proper error boundaries to handle network failures gracefully.
  • Data modeling — designed Pydantic models in FastAPI to validate and shape all API responses, making the front-end integration predictable.

Data flow: The React Native app makes HTTP requests to the FastAPI backend. The backend fetches raw data from the Soccerdata Python library, normalizes it into Pydantic-validated response models, and returns clean JSON. The front-end never touches raw Soccerdata output — the backend owns the data contract.

Challenges & What I Learned

  • Soccerdata normalization — the Soccerdata library returns data in different shapes depending on the league and season. I learned to write defensive normalization code that handles missing fields rather than assuming consistent structure.
  • React Native async state — managing loading, error, and success states for multiple concurrent API calls requires clear patterns. I moved to a consistent fetch-on-mount with loading flag approach that's easy to reason about.
  • Pydantic as a contract — defining Pydantic models upfront forced me to think about the API contract before writing handler logic. This made the front-end integration much smoother because the shape was locked in early.
  • Cross-platform layout — React Native's Flexbox layout is close to CSS but not identical. I learned where the differences are (no grid, different default axis) through trial and error on the standings table layout.
